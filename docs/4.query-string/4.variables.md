# Variables

`default*()` methods (and any incoming `filter`/`select`/`sort`/`aggregate`/`include`/`cast` value) may reference other request input with `$name` — optional, resolves to an empty string if absent — or `$name!` — required, throws a validation error if absent:

```php
public function defaultFilter(): string
{
    return 'author_id:$author_id!';
}
```

Given a request like `GET /posts?author_id=42`, `$author_id!` resolves to `42` before the filter is parsed. If `author_id` is missing from the request, a `ValidationException` is thrown instead of silently filtering on an empty value.

The optional form is useful for filters that should only apply when the caller supplies extra context:

```php
public function defaultFilter(): string
{
    return 'status:$status';
}
```

If `status` is absent, `$status` resolves to an empty string, producing `status:` — an effectively inert clause, since `Filtering` treats it as filtering on an empty value.

Resolution is handled by `Dex\Laravel\Curio\Language\VariableResolver`, and runs against the same request-context collection used for `page`/`size`/`filter`/etc — i.e. any query parameter, not just ones declared in `filterBy()`.

This variable resolution is specific to the HTTP pipeline (`Extensions\Paginator`, the thing `PaginateRequest::paginate()` delegates to). The fluent `Model::curio()`/`Curio` path parses whatever string you pass it as-is, with no `$name` substitution.
