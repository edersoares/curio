# Variables

`default*()` methods (and any incoming `filter`/`select`/`sort`/`aggregate`/`include`/`cast` value) may reference other request input with `$name` — optional, resolves to an empty string if absent — or `$name!` — required, throws a validation error if absent:

```php
public function defaultFilter(): string
{
    return 'author_id:$author_id!';
}
```

Given a request like `GET /posts?author_id=42`, `$author_id!` resolves to `42` before the filter is parsed. If `author_id` is missing from the request, a `ValidationException` is thrown instead of silently filtering on an empty value.

The optional form is useful for filters that should only apply when the caller supplies extra context:

```php
public function defaultFilter(): string
{
    return 'status:$status';
}
```

If `status` is absent, `$status` resolves to an empty string, producing `status:`. A key with no value isn't a `key:value` clause, so the token is read as [free text](/query-string/searching) instead: when `searchBy()` is empty it is discarded and nothing is filtered, but when the query declares `searchBy()` the literal text `status:` is searched for — which will usually match no rows. Prefer the required form (`$status!`) on a query that has free-text search enabled.

Resolution is handled by `Dex\Laravel\Curio\Language\VariableResolver`, and runs against the same request-context collection used for `page`/`size`/`filter`/etc — i.e. any query parameter, not just ones declared in `filterBy()`.

## Variables are client input

A `$name` is filled by whatever the request sent under that key — it is never a server-side value — and it is substituted *before* the string is parsed, so the value is read as query syntax, not as a single value. Given `defaultFilter(): 'owner_id:$owner'`, a request can send `?owner=1 status:draft` and have `status:draft` parsed as a clause of its own.

Every clause still has to pass the same allow-lists as one sent directly in `filter=`, and clauses only ever combine with `AND`, so a variable can add constraints but never remove the ones a `default*()` put there. What it can't do is pin anything down: don't use a `$variable` for a tenant id or the authenticated user. Resolve those on the server — constrain the `Builder` you pass to `paginate()`, or build the value in `FormRequest::prepareForValidation()`.

A `default*()` is also only a default: it is replaced, not merged, as soon as the request sends that parameter itself.

## Fluent path

This variable resolution is specific to the HTTP pipeline (`Extensions\Paginator`, the thing `PaginateRequest::paginate()` delegates to). The fluent `Model::curio()`/`Curio` path parses whatever string you pass it as-is, with no `$name` substitution.
