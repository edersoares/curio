# Including (`include`)

Space-separated relation list. Only relations declared in `includeBy()` (mapped to their own `PaginateQuery` class) are allowed.

An included relation is constrained the way its own endpoint is: by that `PaginateQuery`'s `defaultFilter()`, with `$variables` resolved against the request. `@filter(...)` and `@only(...)` replace the default, as `filter=` does at the top level, and aggregates (`@count`, `@sum(...)`, …) count what the related endpoint would show. In a dotted item (`posts.comments`) every level gets its own default. This applies on the HTTP path only — the fluent `Model::curio()` applies no `default*()` at any level.

```php
public function includeBy(): array
{
    return [
        'author' => AuthorQuery::class,
        'comments' => CommentQuery::class,
    ];
}
```

| Pattern                             | Effect                                                        |
|-------------------------------------|---------------------------------------------------------------|
| `relation`                          | Eager loads the relation                                      |
| `relation:@filter(expr)`            | Eager loads and constrains the parent query via `whereHas`    |
| `relation:@only(expr)`              | Eager loads, filtering only the loaded relation rows          |
| `relation:@limit(n)`                | Eager loads, limiting each parent to at most `n` related rows |
| `relation:@filter(expr):@limit(n)`  | Combines `@filter` and `@limit` (either order)                |
| `relation:@only(expr):@limit(n)`    | Combines `@only` and `@limit` (either order)                  |
| `relation:@count`                   | `withCount('relation')`                                       |
| `relation:@sum(column)`             | `withSum('relation', 'column')` (also `@avg`, `@min`, `@max`) |
| `relation:@count(distinct:column)`  | `COUNT(DISTINCT column)` on the relation                      |
| `relation:@count:@alias(name)`      | Aliases the aggregate column                                  |
| `relation:@count:@only(expr)`       | Filters the rows counted/aggregated                           |

The `expr` inside `@filter(...)` / `@only(...)` is a normal [filter](/query-string/filtering) string, validated against the related `PaginateQuery`'s `filterBy()` — including free text, which searches the related query's own `searchBy()` fields exactly like a top-level `filter=` would (e.g. `include=author:@filter(ada lovelace)` searches `AuthorQuery::searchBy()` inside the `author` relation's subquery).

`@sum`/`@avg`/`@min`/`@max` always require a column argument (`@sum(column)`). `@count` takes no argument (`COUNT(*)`) or `distinct:column` (`COUNT(DISTINCT column)`); `distinct` is not supported on the other aggregators.

`@limit(n)` is only supported on relations that return multiple rows per parent (`HasMany`, `HasManyThrough`, `MorphMany`, `BelongsToMany`, `MorphToMany`, and their singular `HasOne`/`HasOneThrough`/`MorphOne` counterparts) — using it on a `BelongsTo`/`MorphTo` relation throws a validation error, since those return a single related row per parent and limiting would apply a single global limit across all parents' results instead. `@limit(n)` does not itself guarantee row order — pair it with a relation that defines its own ordering (e.g. a `latestPost()` relation defined as `->hasOne(Post::class)->latest()`) if you need deterministic "first N" / "latest N" semantics. `@limit(n)` takes a positive integer no greater than the related query's `defaultMaxPageSize()` (250 by default), and may come before or after `@filter(...)`/`@only(...)`.

Anything else in an `include=` item is a 422 rather than being ignored: an unknown modifier (`posts:@bogus`), `@alias` without an aggregate, `@filter` together with `@only`, a negated relation (`-posts`) or a value (`posts:id,title`).

An `include=` item may go through at most `maxIncludeDepth()` relations (`posts.comments.author` is 3, the default from [`config('curio.include.max_depth')`](/reference/configuration)); a deeper chain fails validation.

## Consuming aggregation includes in a Resource

`relation:@count`/`@sum`/etc. populate Laravel's standard `withCount`/`withSum`/etc. attributes, readable in an API Resource with `whenCounted()`/`whenAggregated()`:

```php
class PostResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id' => (int) $this->id,
            'author' => AuthorResource::make($this->whenLoaded('author')),
            'comments' => CommentResourceCollection::make($this->whenLoaded('comments')),
            'comments_count' => $this->whenCounted('comments'),
            'comments_sum' => $this->whenAggregated('comments', 'author_id', 'sum'),
        ];
    }
}
```
