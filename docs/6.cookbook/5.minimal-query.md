# Minimal query

The `User` endpoint (`GET /api/user`) uses a `PaginateQuery` with no overrides at all:

```php
class UserQuery extends PaginateQuery {}
```

Because every method on `PaginateQuery` defaults to "nothing allowed" (an empty array or empty string), this is a fully functional, safe-by-default endpoint:

- `filter=`, `sort=`, `include=`, `aggregate=`, `cast=` all reject any value, since `filterBy()`, `sortBy()`, `includeBy()`, `aggregateBy()`, `castBy()` are all empty.
- `page=`/`size=` still work, using the package-wide defaults from `config('curio.paginate.*')`.
- The result is a plain, unfiltered, paginated list — `$request->paginate(User::query())` still returns a valid `LengthAwarePaginator`.

This is the right starting point for:

- **A genuinely simple listing endpoint** that only ever needs pagination.
- **Prototyping** — start with nothing allowed, then add exactly the `filterBy()`/`sortBy()`/etc. entries a real client turns out to need, rather than guessing up front.
- **A deliberately locked-down endpoint** where you want pagination without exposing any query surface to filter, sort, or inspect relations — safer than an empty `PaginateQuery` accidentally becoming permissive as the query class grows, since every allowance is opt-in.
