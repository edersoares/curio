# Testing

```bash
composer test                  # run all tests
vendor/bin/pest tests/path/to/Test.php --filter "test name"  # run a single test
composer analyse               # PHPStan static analysis (level max, src/ and config/)
composer format                # Laravel Pint code style
composer coverage               # test coverage with Xdebug
composer mutate                # mutation testing with Xdebug (slow - takes minutes, fails below a score of 80%)
composer test:postgres         # the suite that executes against a real PostgreSQL server
```

The `workbench/` directory is a runnable Orchestra Testbench app (`Author`, `Post`, `Comment`, `User` models with matching queries, requests, controllers and resources) used by the test suite — `composer test` runs it on an in-memory SQLite database — and it's a good place to see the full feature set wired together end-to-end, and is the source for every example in the [cookbook](/cookbook).

Tests are organized to mirror the source: `tests/UseCase/*Test.php` covers each `Language` parser/validator individually (`Filtering`, `Sorting`, `Selecting`, `Aggregating`, `Casting`, `Including`, `Searching`, `Parser`, `VariableResolver`), plus `MalformedInputTest`, which throws hostile and malformed strings at every parameter, and `LimitsTest`, which holds the boundary of every [request limit](/reference/configuration#limits). `tests/Extensions/PaginatorTest.php` covers the end-to-end HTTP/`Paginator` pipeline, and `tests/Extensions/PipelineTest.php` that applying a query doesn't depend on the event dispatcher. `tests/Postgres/*Test.php` is the [PostgreSQL suite](#postgresql-suite) below. `tests/CoverageTest.php` and `tests/ArchTest.php` sit at the root, covering coverage gaps and architectural rules respectively.

## PostgreSQL suite

`composer test` runs on an in-memory SQLite, and most of it asserts the SQL Curio *builds* — which never reaches a database. That is no proof for what only PostgreSQL can run (the `trgm` and `unaccent` search modes, `sort=field:@unaccent`, `EXTRACT()`, `jsonb` containment), so those have a suite of their own, under `tests/Postgres`, that executes every query against a real server:

```bash
docker run --rm -d --name curio-postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=curio -p 5432:5432 postgres:17-alpine

CURIO_POSTGRES_URL=pgsql://postgres:postgres@127.0.0.1:5432/curio composer test:postgres
```

The suite enables the `pg_trgm` and `unaccent` extensions itself, so the user in the URL has to be allowed to. Without `CURIO_POSTGRES_URL` every test in it is skipped rather than failed; CI runs it with `--fail-on-skipped`, against every supported PostgreSQL version.
