# Field aliases

`replaceBy()` lets clients use friendlier or differently-cased query keys than your database columns — applied to `filter`, `sort`, `select`, `aggregate`, and `cast`, before each is validated against its own `*By()` allow-list. It does **not** apply to `include`, since an `include=` key names a relation rather than a field, and aliasing it the same way would risk rewriting a real relation name (`include=author`) into a broken nested-relation lookup.

```php
public function replaceBy(): array
{
    return [
        'author' => 'author.name',
        'authorName' => 'author.name',
        'date-of-birth' => 'date_of_birth',
    ];
}
```

With the map above, all of these are equivalent:

```
filter=author:jane
filter=authorName:jane
filter=author.name:jane
```

```
sort=author
sort=-date-of-birth
```

Aliasing happens before validation, so `filterBy()`/`sortBy()` only need to declare the real field (`author.name`, `date_of_birth`) — not every alias pointing at it.

## Why this matters

`replaceBy()` is a good place to expose:

- **Friendlier names for relation columns** — `author` instead of `author.name`.
- **Case conventions clients expect** — `authorName`/`author-name` alongside a snake_case column, without changing the database schema.
- **Renamed columns** without a breaking API change — point the old query key at the new column name.
