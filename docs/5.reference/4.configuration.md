# Configuration

```php
// config/curio.php
return [

    'query' => [
        'aggregate' => 'aggregate',
        'cast' => 'cast',
        'filter' => 'filter',
        'include' => 'include',
        'page' => 'page',
        'size' => 'size',
        'select' => 'select',
        'sort' => 'sort',
    ],

    'paginate' => [
        'default_page_number' => 1,
        'default_page_size' => 25,
        'default_max_page_size' => 250,
    ],

    'filter' => [
        // Maximum number of clauses in `filter=`, counted after presets are expanded.
        'max_clauses' => 50,
        // Maximum number of relations a filter key may go through.
        'max_depth' => 3,
    ],

    'sort' => [
        // Maximum number of fields in `sort=`.
        'max_fields' => 5,
    ],

    'aggregate' => [
        // Maximum number of items in `aggregate=`.
        'max_items' => 10,
    ],

    'include' => [
        // Maximum relation nesting depth accepted in `include=`.
        'max_depth' => 3,
        // Maximum number of relations in `include=`.
        'max_relations' => 10,
    ],

    'search' => [
        // Options: like, trgm (Postgres), unaccent (Postgres)
        'mode' => 'like',
        'similarity_threshold' => 0.3,
    ],

];
```

Create your own `config/curio.php` with only the sections you want to change — the package's defaults are merged in for the rest (via `CurioServiceProvider::register()`'s `mergeConfigFrom()`).

Defaults are merged one level deep: a top-level section you define (`query`, `paginate`, `filter`, `sort`, `aggregate`, `include`, `search`) **replaces** the package's section, it isn't merged key by key. Copy the whole section you are changing — a `paginate` section holding only `default_page_size` leaves the other two keys undefined, and every request fails. `search` is the exception: its two keys fall back to their defaults (`like`, `0.3`) when absent.

## `query`

Renames the query string parameters Curio reads. Every parameter throughout this documentation (`filter`, `sort`, `include`, `select`, `aggregate`, `cast`, `page`, `size`) is looked up through this map — rename any of them without touching your `PaginateQuery` classes.

## `paginate`

Backs `PaginateQuery::defaultPageNumber()`, `defaultPageSize()`, and `defaultMaxPageSize()` — see [Pagination](/query-string/pagination). Override per query class instead of globally when only one endpoint needs different defaults.

## Limits

An allow-list bounds *which* fields a request may name, not how many times it names them: `ranking:1` repeated a thousand times is a thousand valid clauses, each one a `WHERE` of its own. These keys bound how much a single request can ask the database to do. Exceeding any of them is a validation error (422) under the parameter's own key — `errors.filter`, `errors.sort`, `errors.aggregate`, `errors.include`.

| Key                     | `PaginateQuery` method  | Default | Limits                                                                     |
|-------------------------|-------------------------|---------|----------------------------------------------------------------------------|
| `filter.max_clauses`    | `maxFilterClauses()`    | `50`    | Clauses in one `filter=` string, counted after presets are expanded        |
| `filter.max_depth`      | `maxFilterDepth()`      | `3`     | Relations a filter key may go through (`posts.author.name` goes through 2) |
| `sort.max_fields`       | `maxSortFields()`       | `5`     | Fields in `sort=`                                                          |
| `aggregate.max_items`   | `maxAggregateItems()`   | `10`    | Items in `aggregate=`                                                      |
| `include.max_depth`     | `maxIncludeDepth()`     | `3`     | Relation nesting depth of one `include=` item                              |
| `include.max_relations` | `maxIncludeRelations()` | `10`    | Relations in `include=`                                                    |

The config sets the default for every query; override the method on a `PaginateQuery` when one endpoint needs a different budget. On the fluent `Model::curio()` path the same methods are read from the model.

```php
class ReportQuery extends PaginateQuery
{
    public function maxFilterClauses(): int
    {
        return 200;
    }
}
```

A few details worth knowing:

- **Free text is one clause**, however many words it has — it is merged into a single search clause.
- **A filter scoped to a relation has a budget of its own.** `include=posts:@filter(...)` is checked against the limits of the `posts` query, separately from the request's own `filter=`.
- **The depth limits exist because relation chains can cycle.** `posts.author.posts` is allow-listed at every level, so `includeBy()` alone can't bound it: every extra level of an `include=` multiplies the serialized payload, and every extra level of a `filter=` nests another `EXISTS`.
- **There is no "unlimited".** A limit is always a number; raise it for the endpoint that needs more.

## `search`

Backs `PaginateQuery::searchMode()` and `searchSimilarityThreshold()` — see [Free-text search](/query-string/searching). `mode: 'trgm'` requires the Postgres `pg_trgm` and `unaccent` extensions; `mode: 'unaccent'` requires just `unaccent`. Neither is automatically enabled or verified by the package.

There is no global sort mode: accent-insensitive sorting is opted into per field via the `:@unaccent` modifier (`sort=email:@unaccent`) — see [Sorting](/query-string/sorting).
