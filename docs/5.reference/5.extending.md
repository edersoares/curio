# Extending Curio

Every fluent DSL call (`filter()`, `sort()`, `select()`, `aggregate()`, `include()`, `cast()` — whether from `Model::curio()` or through the HTTP pipeline) parses its argument immediately and queues the result; nothing touches the query builder until a terminal call (`get()`, `paginate()`, `first()`, ...) actually runs.

At that point, one `Dex\Laravel\Curio\Events\ApplyPending` event is dispatched carrying every queued token, and a set of listeners registered in `CurioServiceProvider::boot()` each pick out the tokens they care about and apply them — one listener per DSL type, plus a couple of cross-cutting ones (field-alias resolution via `replaceBy()`, and registering relation-aggregate/include aliases as sortable).

It's a normal Laravel event, so your own application can hook a listener onto it too — for auditing, metrics, or reacting to a request's shape:

```php
use Dex\Laravel\Curio\Events\ApplyPending;
use Illuminate\Support\Facades\Event;

Event::listen(ApplyPending::class, function (ApplyPending $event) {
    Log::info('curio query', [
        'model' => $event->builder->getModel()::class,
        'types' => array_unique(array_column($event->tokens, 'type')),
    ]);
});
```

## What the event carries

| Property          | Type                    | Notes                                                                                                                                                                                                                    |
|-------------------|-------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `$event->tokens`  | array of parsed clauses | Every token queued since the last dispatch, each tagged with its own `type` (`filter`, `sort`, `select`, `aggregate`, `include`, or `cast`). Mutable — a listener registered before Curio's own can rewrite it in place. |
| `$event->builder` | `Builder\|Relation`     | The Eloquent builder (or relation, for a nested/scoped context) being queried.                                                                                                                                           |
| `$event->query`   | `PaginateQuery`         | The bound query class, or a synthesized adapter over the model's own `YourCuriosity` methods on the unbound/trusted path.                                                                                                |

## Listener order matters

Laravel dispatches listeners in registration order. Register your own listener from your application's own service provider `boot()` — since Laravel boots the framework's own providers (including `CurioServiceProvider`) before application providers, your listener naturally runs *after* Curio's built-in ones, so it sees tokens after alias resolution and type-specific application have already happened. If you need to inspect or rewrite tokens *before* Curio's own listeners act on them, you'd need to register earlier in the boot cycle instead.
